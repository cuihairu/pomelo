# 12 · 扩展:MMU 与真隔离

这一章没有对应代码——它是把 Pomelo 变成“真”微内核的路线图。

## 现在的墙是纸糊的

回顾[第 1 章](/guide/intro):fs/tty/shell 靠**纪律**隔离。任何一个任务写坏指针,
都能踩到内核的数据结构;任何任务一行 `outb` 就能抢走别人的硬件。逻辑微内核
教的是结构,但结构挡不住 bug。

MMU(内存管理单元)提供两件硬件机制,把纸墙换成砖墙:

1. **分页**:每个任务一张页表,虚拟地址 → 物理地址各翻各的,互相看不见;
2. **特权级(ring3)**:用户代码执行特权指令直接触发异常,进内核只能走系统调用门。

## 升级清单

好在这种改动是**加法**,前面每一章的结构都原样保留:

| 章 | 现状 | 升级后 |
| --- | --- | --- |
| [boot](/guide/boot) | 一张全地址 GDT | 内核/用户两个代码段、两个数据段 |
| [boot](/guide/boot) | 无页表 | 建内核页表 + 每任务页表,`cr3` 换页即换世界 |
| [sched](/guide/scheduling) | 任务 = 栈 + 现场 | 多一个 `pdir`(页目录指针),切换时一并换 |
| [syscall](/guide/syscall) | ring0 软中断 | 同一扇 `int 0x80` 门,但入口切到 ring0、返回降回 ring3 |
| [ipc](/guide/ipc) | 消息指针直接传 | 内核把消息从发送方缓冲**拷贝**到接收方缓冲(否则就是共享内存漏点) |
| [fs/tty](/guide/fs-server) | 服务直接 `outb` 硬件 | 硬件访问被页保护拦下,驱动下沉成新服务,经内核代理访问 |

值得注意:shell 的代码**一行都不用改**。它本来就只发消息。这就是微内核结构
投资的回报——当初守规矩,如今升级免费。

## 内核从此多了第五件事

加了分页,内核就得管物理内存(分配页帧)和地址空间(页表),通常还有页面
换出。这就是为什么真实微内核(Mach、seL4、Fuchsia)的内核都比 Pomelo 大:
**MMU 管理本身是躲不开的内核职责**。我们不是不想写,而是不把它和前面十二章的
概念混在一起教。

## 建议的阅读顺序

如果想动手把 Pomelo 推到这一步:

1. 先读任何一份 x86 分页资料,理解两级页表和 `cr3`;
2. 给内核加物理页分配器(一个位图就够,20 行);
3. 加用户页表 + ring3 段,把 shell 先切过去跑通;
4. 最后改 IPC 为内核拷贝,并给每个服务立单独页表。

每一步都能在 QEMU 里立刻看到效果,失败也不会很难排查——这个项目小到
**一切状态都看得见**。

祝玩得开心。
